## 1. 提交源码与线上对应

DeepSpace 云仓库是唯一发布源。GitHub 的 `main` 分支用于评审和复现，其中 `deepspace-app/` 是最终发布提交的应用文件快照，不混入开发分支中的未发布功能。

仓库根目录 `release/deepspace.json` 记录线上 release ID、云源码提交、平台公开 release stamp，以及全部应用文件的 Git blob 校验值。它放在应用目录外，避免发布编号与源码自身产生循环引用。该记录在部署和线上验证后生成。

从提交仓库根目录执行：

```sh
python scripts/verify-deepspace-source.py
python scripts/verify-deepspace-source.py --live
```

第一条逐文件检查缺失、额外或修改过的应用源码，Windows 文本换行经 Git 规范化，图片按原始字节校验。第二条还检查 DeepSpace 原生公开发布标记和应用健康状态。该清单是可复核的发布记录，不是独立第三方签名。

提交入口：[GitHub 提交分支](https://github.com/Gary22222222/friends-fridge-submission/tree/main)。请从 `deepspace-app/` 运行应用；开发分支不作为本次提交入口。

## 2. 查价体验

### 剩余次数

- 预算面板显示服务端返回的个人剩余次数、应用共享剩余次数和重置时间；实际可用次数取两者较小值。
- 价格采集每天每用户三次、全应用八次；附近商店查询保持独立的每日额度。
- 配额按 UTC 零点重置。缓存价格和继续已有任务不会占用新的价格采集次数；已开始的供应商采集尝试即使失败，仍计入尝试次数。
- `LookupRoom` 独立保存查询状态和额度，计数在 SQLite 同步事务中更新。库存与交接仍由原库存房间处理。
- 新计数器从这次更新首次使用时开始记录，不导入旧计数器无法读取的历史次数；首次使用当天页面会显示这一说明。它不重置平台 credits，也不代表采集免费。

### 断网与刷新后续查

- 发出请求前，浏览器先保存请求 ID；获得任务 ID 后保存同一任务的凭据。
- 网络中断后显示 **Resume lookup**。保持相同预算、人数、来源和分组时，重试或刷新页面后继续原任务，不重新创建供应商任务。
- 状态查询遇到暂时网络问题会有限重连；终止、超时、权限错误或过期任务会给出明确提示。
- 服务端按账号隔离任务；同一 ID 改用不同条件会拒绝。更新前仍在运行的旧任务可以按原所有者转入查询状态存储继续读取。
- 浏览器凭据按用户名隔离，仅含请求条件、ID 和时间，不保存令牌或照片。凭据和服务器任务保留约一小时。
- 供应商启动后、任务 ID 回写前若发生异常，页面会超时提示人工处理，不自动再启动一次；不承诺跨供应商和本地存储的绝对 exactly-once 计费。

### 报价过期

- 以原报价时间为准，满 15 分钟主动撤下预算推荐与过期商品价格，显示 **Refresh prices**。
- 切回页面时也会检查时效；修改预算、人数或离开账号会清理相应显示与计时器。
- 到期只提示用户主动刷新，不自动调用收费查询。重新查价会先利用仍有效的商品缓存。

## 3. 零库存图片

Icons 视图中，数量为零的食物图片变成灰色并降低透明度，边框使用虚线。仍然只显示图片，不额外叠加名称或数字。

零库存图片仍可点击编辑，悬停提示与辅助技术标签会说明 Out of stock；List 视图继续显示原有缺货文字。增加数量后，图片恢复正常颜色。

## 验证范围

- 单元测试覆盖个人/共享额度边界、UTC 重置、请求凭据恢复、账号隔离和报价时效。
- 浏览器测试在真实后端完成一次零预算查询后故意丢弃响应，刷新页面续查并断言请求 ID 相同、额度不重复减少；用浏览器时钟验证过期不会发起新的收费请求。
- 库存测试使用 40 种临时食物，验证尺寸、滚动、图片编辑和零库存灰显后仍可编辑，结束后清理临时数据。
- 真实供应商测试单独开启，验证新采集只扣一次额度，重放已存在请求不再扣次数。

实际发布编号、最终源码清单和各轮测试结果见提交仓库根目录 `release/deepspace.json` 与 `release/evidence/verification.json`。这类机器记录和自动化不代替申请者亲自完成登录、真机和照片识别检查。
